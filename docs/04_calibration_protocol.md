# 04 SVMA 超參數的 held-out 校準流程（凍結版本 v1.0 的來源）

整理於 2026-10-17，給論文的 Method（超參數選擇）與 Appendix（完整校準紀錄、偏離事先規則的地方）使用。
凍結版本的設定表見 [03_experiment_plan.md](03_experiment_plan.md) §2.6。

## 0. 一句話摘要（論文可直接改寫）

> SVMA 的所有超參數（覆蓋 tile 比例 m/K、打分窗口 S、預設 budget）都只在兩個與測試集不重疊的 held-out 校準集上決定：InfoVQA train 的 600 題與 MME-RealWorld 扣掉 Lite 後的 600 題。測試集不參與任何選擇。選擇依序為：(A) 掃 m/K，(B) 量保留率與 TTFT 決定預設 budget，(C) 固定 m 掃 S。之後提出的一個候選改動（打分窗口隨細節網格放大）在 held-out 上用事先定好的三條標準檢驗，沒有通過，因此未採用。

## 1. 原則

1. **測試集不參與選擇**：DocVQA val、InfoVQA val、HR-Bench 4K、MME-RealWorld Lite、V* Bench 只用來報告結果。
2. **看測試集只能做診斷**：可以分析錯在哪裡；要改設定必須回到校準集驗證，通過後重跑所有測試集。
3. **判斷標準事先定好**：每一輪掃描前先寫下怎麼選，結果出來後照規則決定；若偏離規則，記錄原因並在論文附錄說明。
4. **統計檢定**：所有比較都在相同題目上做配對 bootstrap（paired bootstrap，重抽 2,000 次；3b 用 4,000 次；seed 0），報告平均差與 95% CI，CI 不含 0 視為顯著。
5. **舊設定為什麼要重新校準**：v0 的打分窗口表（`LEGACY_QATTN_TILES_M1`）是在 InfoVQA val（＝測試集）上調的，m = 0.75K 也是看測試集子集決定的，屬於 test leakage，因此全部捨棄、在 held-out 上重新決定。

## 2. 校準集與測試集

### 2.1 校準集

| 名稱 | 建立方式 | 題數 | 評分 | 代表的任務 |
|---|---|---|---|---|
| `infovqa_train_calib` | InfoVQA **train** split，以 `random.Random(0)` 打亂索引後取前 600 題 | 600 | ANLS（官方算法，threshold 0.5，不做答案抽取） | 文件、資訊圖表 |
| `mme_rw_calib` | MME-RealWorld 完整版（英文 23,609 題）→ 扣掉 Lite 的題目（1,787 題）→ 再扣掉「圖片出現在 Lite 裡」的題目（2,654 題）→ 剩 19,168 題；5 個 Subtask 各自依 Question_id 排序後用 `random.Random(0)` 打亂，各取 120 題 | 600 | 選擇題 accuracy（輸出字母 = 正解字母） | 高解析度真實場景（自駕、圖表、監控、OCR、遙測） |

- Lite 與完整版的對應：Question_id 與圖片路徑格式不同，用「題目文字 + 選項 + 圖片檔名」比對，Lite 的 1,919 題全部找得到（Lite 本身有 137 題重複，唯一題目 1,782 組）。
- 驗證：校準集與 Lite 的題目交集 = 0，圖片交集 = 0。
- 程式：`prepare_mme_realworld.py`（產生 `~/datasets/MME-RealWorld/calib600.json` 與 `lite.json`）、`process_common.load_infovqa(..., sample_seed=0)`、`process_common.load_mme_realworld`。
- MME-RealWorld 的 prompt 用官方作答指示：「Select the best answer to the above multiple-choice question based on the image. Respond with only the letter (A, B, C, D, or E) of the correct option.\nThe best answer is:」

### 2.2 測試集（只報告）

| 名稱 | 題數 | 評分 |
|---|---|---|
| DocVQA val | 5,349 | ANLS |
| InfoVQA val | 2,801 | ANLS |
| HR-Bench 4K | 800 題（200 組） | CircularEval（同一組 4 種選項排列全對才算對） |
| MME-RealWorld Lite | 1,919 | 選擇題 accuracy |
| V* Bench | 191（direct_attributes 115 + relative_position 76） | 選擇題 accuracy |

- 為什麼 Lite 當測試集而不是校準集：Lite 是 VLMEvalKit / lmms-eval 的標準切分，數字可跟文獻比較；校準只需約 600 題，完整版扣掉 Lite 後有 19,168 題可抽；反過來的話測試集要用完整版（88 GB 圖片，成本高十倍以上），而且非標準。
- DocVQA 沒有帶答案的 train split，文件類由 InfoVQA train 代表（論文要註明）。

### 2.3 衡量指標

- **分數**：各校準集的 ANLS / accuracy（%）。
- **保留率**：SVMA 分數 ÷ 同一校準集的 uncompressed 分數。uncompressed：InfoVQA train 83.9、MME-RW calib 59.5。
- **平均保留率**：兩個校準集保留率的平均。
- **最差任務保留率**：6 組（InfoVQA + MME-RW 的 5 個 subtask）中保留率最低的一組。
- **TTFT**：`bench_metrics.py`，每個校準集取 51 張圖、第 1 張 warmup 不計、取中位數，每張 GPU 只跑一個程序（RTX A6000）。uncompressed：InfoVQA train 1.21 s、MME-RW calib 2.81 s。
- **記憶體增量**：峰值記憶體減掉模型權重（17.06 GB）。uncompressed：1.60 / 3.20 GB。

## 4. 保留率、TTFT 與預設 budget（2026-10-14）

- **做法**：兩個校準集都跑 uncompressed（batch 1）；在乾淨環境量 m/K ∈ {0.5, 0.75, 1.0} 的 TTFT。
- **程式**：`bench_metrics.py --svma_m_fracs 0.5,0.75,1.0 --warmup_images 1`；結果 `results/calib/metrics/metrics_<dataset>.csv`。

| budget | m/K=0.5 平均保留率 / TTFT | m/K=0.75 | m=K（純覆蓋） |
|---|---|---|---|
| b1024 | 89.7% / 0.90 s | 91.2% / 0.69 s | 88.5% / 0.40 s |
| b1536 | 95.7% / 0.99 s | 94.3% / 0.89 s | 96.2% / 0.45 s |
| b2048 | 95.9% / 1.08 s | 95.5% / 1.00 s | 96.0% / 0.56 s |
| b2560 | 98.9% / 1.19 s | 97.9% / 1.15 s | 97.7% / 0.69 s |
| b3072 | 99.3% / 1.41 s | 99.1% / 1.32 s | 100.1% / 0.80 s |

最差任務保留率（6 組中最低，幾乎都是 Remote Sensing）：

| budget | m/K=0.5 | m/K=0.75 | m=K |
|---|---|---|---|
| b1024 | 76% | 77% | 80% |
| b1536 | 85% | 72% | 86% |
| b2048 | 85% | 72% | 74% |
| b2560 | 94% | 82% | 69% |
| b3072 | 86% | 83% | 78% |

- 記憶體增量（扣權重）全部在 0.28~0.75 GB。
- **關鍵發現**：純覆蓋的平均保留率與有細節選擇的設定相同、TTFT 約一半；細節選擇換到的是最差任務的穩定度。
- **決定（使用者選「方案 A」）**：
  - **m/K = 0.5**：平均與 0.75、1.0 打平，但最差任務保留率最穩（b2048 85% vs 純覆蓋 74%、b2560 94% vs 69%），HR 類任務是論文主戰場。
  - **預設 budget = 1536**：保留率轉折點（b1024 90% → b1536 96%，b2048 沒有再進步）。
  - 論文定位：主打「最差任務也穩、成本有上限」，純覆蓋放 ablation 誠實呈現。
- **注意**：階段 A 時兩張 GPU 各跑兩個程序，當時記錄的 TTFT 不可信，第 4 節的 TTFT 是另外在每張卡只跑一個程序時量的。

## 5. 階段 B：打分窗口 S（2026-10-14）

- **做法**：固定 m = ⌊K/2⌋，S ∈ {0, S0/2, S0, 1.5 S0, 2 S0}（S0 = 舊規則在 m=K/2 下的值：b1024 10、b1536 9、b2048 8、b2560 7、b3072 7）。兩個校準集 × 5 個 budget，accuracy 600 題、TTFT 50 張圖。
- **程式**：`run_calibrate_stageB.sh`（`STAGE=S ./run_calibrate.sh` + `bench_metrics.py --svma_s_mults 0,0.5,1,1.5,2`）；結果 `results/calib/<dataset>/svma_b<B>_m<m>_S<S>_*.json`、`results/calib/metrics/metrics_S_<dataset>.csv`。
- **事先定的規則**：每個 budget，平均保留率與最差任務保留率都在最佳值 1 個百分點內的 S 中取最小；b1536 另外希望 TTFT ≤ 0.8 s（最差任務掉不超過 2 個百分點）。

| b2048 | 0 / 4 / 8 / 12 / 16 | 95.1 / 96.7 / 95.9 / 95.5 / 96.2% | 75.4 / 84.6 / 84.6 / 81.5 / 83.1% | 0.72 / 0.92 / 1.08 / 1.26 / 1.45 s |

- **規則選出**：{1024: 5, 1536: 13, 2048: 4, 2560: 3, 3072: 14}。
- **問題**：最差任務每組只有 120 題（1 題 ≈ 1.5 個百分點），最差的是哪一組會隨 S 改變（b1536 S=4 最差是 Diagram、S=13 最差是 Remote Sensing），規則被雜訊主導。配對 bootstrap：b1536 S=13 vs S=4、b3072 S=14 vs S=3 的差距都不顯著（只有 OCR 個別顯著，且被 Remote Sensing 的反向差距抵消）。
- **偏離事先規則（使用者同意，論文附錄要註明）**：一律取 **S = S0/2** → `QATTN_TILES_BY_BUDGET = {1024: 5, 1536: 4, 2048: 4, 2560: 3, 3072: 3}`。b1536 因此是 S=4：平均保留率 95.6%、TTFT 0.77 s（S0=9 時 0.99 s）。
- **附帶的顯著 ablation（可放論文）**：S=0（只靠 prior、不做 q_attn）比 S0/2 差：Remote Sensing b1024 −10.8 [−18, −4]、b1536 −10.8 [−18, −4]；Monitoring b2560 −7.5 [−12, −3]。→ 依問題打分在局部細節任務上有實質貢獻。
- **S 超過 S0/2 沒有可靠增益**（CI 大多含 0），只多花 TTFT。
- **驗證**：新預設跑 8 題，答案跟階段 B 的 S=4 逐題相同。

## 6. 診斷（3a，2026-10-16~17，只看測試集、不改設定）

- **動機**：v1.0 在測試集上 b1024 顯著輸 IF-Prune（DocVQA −2.81、InfoVQA −2.98、V* −6.81），HR-Bench 4K 新舊設定差距不顯著。
- **做法**：V* 每題有目標物件的 bbox；以「bbox 中心落在哪塊細節 tile」判斷目標 tile，對照 SVMA 實際選進 KV 的 tile 與 prior 排名（`internvl_stream.py` stats 新增 `prior_ranked`，只記錄、不影響選擇）。結果 `results/diagnostics/vstar_selection/`。

| budget | 命中率 | 命中時正確率 | 沒命中時正確率 | prior 沒排進窗口 | 進窗口但 q_attn 沒選 | 目標進窗口後 q_attn 選中率（隨機） |
|---|---|---|---|---|---|---|
| b1024 | 69.1% | 90.91 | 44.00 | 26.2% | 4.7% | 94%（40%） |
| b2048 | 73.3% | 90.00 | 41.86 | 22.5% | 4.2% | 92%（50%） |
| b3072 | 80.1% | 88.89 | 53.57 | 14.7% | 5.2% | 70%（33%） |

- 目標落在 prior 前 N 名的比例（b1024）：N=5 73.8%、8 85.3%、10 89.5%、12 95.3%、15 97.4%；細節網格中位數 24 塊；目標 prior 排名中位數在前 10~12%。
- 64% 的目標物件在 b1024 覆蓋圖裡短邊 < 14 px（不到一個 ViT patch）。
- **結論**：q_attn 精準，主要錯誤來源是 prior 的打分窗口太小（召回率不足）。→ 提出 3b 候選規則。

## 7. 候選改動 3b：打分窗口隨細節網格放大（2026-10-16~17，未採用）

- **規則**：直接保留 + 打分的塊數 ≥ ⌈f × 細節網格塊數⌉（`svma_config.grid_qattn_tiles`；`--qattn_grid_frac f`，預設關閉）。
- **掃描**：f ∈ {0.2, 0.3, 0.4, 0.5}（使用者同意的是 0.3 / 0.4 / 0.5；smoke test 發現 MME-RW 的圖幾乎都切滿 45 塊、f=0.4 要打分 18 塊，所以多加較便宜的 0.2），m、S 用現行預設，兩個校準集 × b1024~b3072。
- **程式**：`run_calibrate_stageG.sh`；結果 `results/calib/<dataset>/svma_b<B>_m<m>_gf<f>_*.json`、`results/calib/metrics/metrics_G_<dataset>.csv`。
- **事先定的三條標準（全部通過才採用）**：
  1. 平均保留率不比現行預設低超過 0.5 個百分點；
  2. MME-RW 的局部細節題（Remote Sensing + Monitoring + Autonomous Driving，360 題）相對現行預設顯著進步；
  3. b1536 的 TTFT 增加 ≤ 0.3 s。

- **結果**：四個 f 都沒有同時通過三條標準 → **不採用，維持 v1.0**。唯一顯著的一格（b1024 f=0.2）是 20 次檢定中的 1 次，合併後不顯著，不事後挑選。
- **可能原因**：MME-RW 的局部細節題多要看整個場景（計數、交通），不像 V* 集中在單一小物件；MME-RW 的圖幾乎切滿 45 塊，窗口變大後 q_attn 選錯的機會也變多；MME-RW 沒有 bbox，無法直接驗證命中率。
- **論文寫法**：3a 的診斷當方法分析（命中時約 90%、q_attn 精準度 92~94%、主要錯誤來源是 prior 召回率）；3b 如實報告「擴大窗口在 V* 提高命中率，但在 held-out 沒有穩定增益，因此未採用」，列為未來方向（改進 prior）。

## 7b. 候選改動 v1.1：打分 query 與 tile 聚合（2026-10-25，進行中）

- **動機（來自測試集診斷，不是調參）**：
  1. HR-Bench 4K 的 v1.0 在 27% 的組（同題 4 種選項排列）選到的 tile 不一樣。原因是 prior / q_attn 的 query 是 text_after 全部的位置（含選項、作答指示、template）。CircularEval 要 4 題全對，選擇不穩直接扣分（b2560 這 55 組比 token 級方法低 9~15 分；選擇一致的 145 組 FoveaTile 反而最好）。
  2. HR-4K 的落後集中在 single（單一小物件）題；prior 對每塊細節 tile 取 patch 平均，小物件的尖峰被背景稀釋。
  3. HR-8K pilot（50 組）中 FoveaTile 隨 budget 增加不升反降，指向 tile 選擇是瓶頸。
- **改動（`svma_config.QUERY_MODE` / `TILE_AGG`；`--query_mode` / `--tile_agg`）**：
  - A：query ∈ {`all`（v1.0）, `stem`（只用問題主幹的 token 列；causal attention 下主幹看不到選項，數學上與選項順序無關）, `stemopt`（另組「主幹 + 依字母排序的選項」當打分 query）}
  - B：tile 聚合 ∈ {`mean`（v1.0）, `top0.1`, `top0.25`（tile 內前 10% / 25% 的 patch 或 token 取平均）}，prior 與 q_attn 都套用
- **實作驗證**：新程式碼在 `all`/`mean` 下與 v1.0 校準結果 bit-identical（MME-RW calib b1536 前 12 題答案 12/12、tile 12/12）；HR-4K 前 10 組（只看 tile、不看答案）選擇一致率 v1.0 7/10 → `stem` / `stemopt` / `stem+top0.1` 都是 10/10。
- **掃描**：8 個變體（3 × 3 扣掉 v1.0）× b1024 / b1536 / b2560 × 兩個校準集 = 48 組；m、S 用 v1.0 預設；v1.0 對照沿用 `svma_b<B>_m<m>_S<S>` 既有結果。程式 `run_calibrate_v11.sh`。
- **事先定的判斷標準（結果出來前寫下）**：
  - **採用為改進（三條全部通過）**——同 3b：
    1. 3 個 budget 各自的平均保留率都不比 v1.0 低超過 0.5 個百分點；
    2. MME-RW 局部細節題（Remote Sensing + Monitoring + Autonomous Driving，360 題）3 個 budget 合併（1,080 組配對）相對 v1.0 顯著進步（paired bootstrap 4,000 次、seed 0，CI 下界 > 0）；
    3. b1536 的 TTFT 增加 ≤ 0.3 s（單程序、batch 1、51 張圖中位數，選定後量）。
  - **只為排列不變性採用 A（無顯著增益時）**：`stem` 或 `stemopt` 搭 `mean`，通過標準 1、3，且局部細節題合併 Δ 的 CI 下界 > −1.0（不劣於 v1.0）。理由事先說明：選項順序不該影響要看哪裡，這是設計性質，CircularEval 類評測直接受益。
  - 多個候選通過時：取局部細節題合併 Δ 最大者；彼此差距不顯著時取較簡單的（`stem` 優先於 `stemopt`，`mean` 優先於 `top`）。
  - 都不通過：維持 v1.0，如實報告。
- **之後**：選定的設定凍結為 v1.1，重跑 HR-4K / HR-8K（及其他測試集）。論文附錄註明這次改動的動機來自測試集錯誤分析。
- **追加變體 `sortopt`（2026-10-25 19:40，看過 MME-RW 上 `stem` / `stemopt` 的結果之後才加入，需在附錄註明）**：
  - 看到的結果：MME-RW 局部細節題 3 個 budget 合併，所有 8 個變體都比 v1.0 差（`stem` −3.33、`stemopt` −2.13，CI 都不含 0；只有 `all/top0.25` −1.11 不顯著）→ 依規則已確定都不採用；InfoVQA 部分提前停止（不影響判斷）。
  - 推測：v1.0 query 裡最後的 template 位置（`assistant\n`）讀過整題與所有選項，是最有用的 query；`stem` / `stemopt` 都把它排除了。
  - 改動：打分用的 prompt 把選項文字依字母排序後重新配字母（格式、作答指示、template 都不變），query 用全部列（同 v1.0）。沒有選項的題目（InfoVQA）跟 v1.0 完全相同，所以只跑 MME-RW 的 3 個 budget；聚合只用 `mean`。
  - 判斷：只適用「只為排列不變性採用」那條（標準 1 + 局部細節題合併 Δ 的 CI 下界 > −1.0 + 標準 3）；不論結果如何，不再追加其他變體。
  - **結果（2026-10-25 20:00）**：平均保留率 b1024 89.45%（−0.14）、b1536 95.01%（**−0.56**）、b2560 99.09%（+0.28）；局部細節題合併 Δ = −0.19 [−0.93, +0.46]（非劣）。MME-RW 逐題：b1024 變對 7 / 變錯 8、b1536 變對 5 / 變錯 9、b2560 變對 6 / 變錯 4。
  - 標準 1 在 b1536 差門檻 0.06 個百分點（MME-RW 600 題中淨少答對 4 題）→ **照事先規則不通過**。最終決定：**維持 v1.0**（使用者 2026-10-25 決定，不放寬門檻）。論文把 query ablation 當負面結果報告：只用問題主幹 −3 分；排序選項可做到排列不變而不掉分。

## 7c. 候選改動：prior 的 head 選擇（A1）與問題無關基準校正（A2）（2026-10-25，進行中）

- **動機（測試集診斷）**：V* 上 FoveaTile 命中目標 tile 時正確率 87.9（b1536，高於 uncompressed 83.8），沒命中時 48.0；輸給 token 級方法的題目約 60% 是沒命中。命中率 b1536 只有 73.8%，短邊 < 30 px 的目標只有 68.5%。→ 改進 prior 的排序。
- **校準集（新建，held-out，有 bbox）**：`prepare_needle_calib.py`，COCO val2017 的圖拼成 4×4（2248×1500），每張挑一個整張大圖只出現一次的物件、拼圖後短邊 6~60 px，題目照 V* direct_attributes 格式問顏色（選項隨機，不評答案）。300 張，seed 0；前 150 張 `fit`、後 150 張 `val`。目標短邊中位數 30 px、< 30 px 佔 52%（V* 47%）。
  - 為什麼不用 HR-Bench 8K 校準：HR-4K 與 HR-8K 的 159 個問題文字完全相同（題目 + 選項 169 組一致），8K 校準、4K 測試等於在測試題上調；而且 HR-Bench 沒有 bbox，無法逐 head 量命中率。
- **指標**：候選召回率 = 目標 tile（與 bbox 重疊的細節 tile；每個目標至少一塊）落在 prior 前 C 名（C = 直接保留 + 打分窗口 = slots − a + S；b1024 / b1536 / b2560 = 5 / 5 / 7）。只跑 prior 那次 forward，不生成答案。
- **變體**：
  - v1.0：第 21~28 層、全部 head 平均、text_after 全部列。
  - A1：每個 (layer, head) 在 `fit` 上的單 head 召回率（3 個 budget 平均）排序，取前 k 個 head 平均，k ∈ {2, 4, 8, 16, 32}。
  - A2：問題無關基準 = 同一張圖配上通用問題「Describe this image.」的 attention（多一次短 forward）或 text_after 第一個 token（`\n`，不多算）；校正方式 ratio = p_q / (p_base + ε) 或 sub = p_q − p_base（p = 對覆蓋 patch 正規化後的 attention）。套在 v1.0 的 head 與 A1 選出的 head 上。
- **事先定的選擇規則**：
  1. 在 `val` 上取 3 個 budget 平均候選召回率最高的變體；跟較簡單的變體差距 < 1 個百分點時取較簡單的（v1.0 < A2-`\n` < A1 < A2-generic，依額外成本排序）。
  2. 選出的變體 `val` 召回率要比 v1.0 高 ≥ 3 個百分點（約 V* 命中率的雜訊幅度），否則不進入 accuracy 驗證。
  3. 通過後在 MME-RW + InfoVQA 校準集（b1024 / b1536 / b2560）用 3b 的三條標準驗證 accuracy；通過才凍結並跑測試集（V*、HR-4K、HR-8K）。
- **命中率結果（2026-10-25 21:00，`results/diagnostics/prior_heads/needle_calib/analysis.txt`）**：
  - v1.0 val 平均 72.7%（b1024 / b1536 / b2560 = 69.3 / 69.3 / 79.3）。A2 單獨幾乎沒效果（72.4~72.9）；A1 是主要增益：top2 76.4、top4 75.1、top32 75.3。
  - fit 上單 head 召回率最高：(18, 26) 77.6、(19, 18) 75.1、(25, 12) 73.8……；比 v1.0 好的單 head 只有 9 個（共 21 層 × 32 = 672）。
  - 規則 1：val 最高 `A1-top2+A2-gen-ratio` 77.6；差距 < 1 的較簡單者為 `A1-top2+A2-nl-ratio` 76.9 → **選 A1-top2+A2-nl-ratio**（head = (18, 26)、(19, 18)，`svma_config.PRIOR_HEADS_A1`）。
  - 規則 2：76.9 − 72.7 = **+4.2 ≥ 3 → 通過**，進入 accuracy 驗證。
  - 實作驗證：pipeline 的 `coverage_prior(heads=…, base="nl", base_mode="ratio")` 與離線分析的前 5 名一致 10/10；v1.0 重建與 pipeline 一致 60/60。
  - 附帶：選出的 head 在第 18~19 層，prior forward 只需跑到第 20 層（q_attn 本來就要到第 20 層），預期 TTFT 不增反減。
- **accuracy 驗證結果（2026-10-25 21:30）**：

| | b1024 | b1536 | b2560 |
|---|---|---|---|
| MME-RW calib（v1.0 → A1+A2） | 56.00 → 54.83 | 57.67 → 57.50 | 59.33 → 59.67 |
| InfoVQA train calib | 71.36 → 70.61 | 79.05 → 77.88 | 82.13 → 80.86 |
| 平均保留率 Δ | −1.60 | −0.83 | −0.85 |

  - 標準 1（每個 budget 不低於 −0.5）：**✗**（三個 budget 都低於）。標準 2：局部細節題合併 Δ = **−2.22 [−4.35, −0.09]**，顯著變差 **✗**。→ **不採用，維持 v1.0**（TTFT 未量）。
  - MME-RW subtask：Remote Sensing 三個 budget 都變差（−4.2 / −8.3 / −2.5），OCR 與 Diagram 小幅變好。
  - 推測：合成拼圖（找一個有名字的 COCO 物件、格子間有明顯邊界）跟真實高解析度場景分布差距大；只用 2 個 head 的 prior 太窄，不適合計數 / 場景題與文件題。命中率在合成集 +4.2 沒有轉移到真實資料。
  - 論文：列為負面結果（prior 的 head 選擇在合成 needle 集有效、在真實校準集無效），不在測試集上評估此變體。
